## For the gun-record build

Names as built, word for word, in `lib/guns.js`:

- **`fromRecords(records, raw)`** — `records` is a list of gun records `{ id, name, fields: { game: {...} } }`; `raw` is the game's own data with its sources, `require('./lib/data').load().raw`. Returns the rifle set the screens use: an object keyed by id, in the records' order, each entry the `game` section with every figure reduced to its value and `name` added. Throws a `RecordError` (exported) whose message names the gun, the fault and the valid values. It refuses: an id that is not lowercase letters, digits and hyphens; a missing name; a missing `fields.game`; a missing required field (`caliber`, `playable`, `barrelIn`, `sightHeightIn`, `boreOffsetMoa`, `recoilFactor`, `sights`, `defaultSight`, `loads`, `firstCourse`) or an unknown one (the only optional field is `sightLeaf`); a bare number or a figure without a source or an estimate (the data file's own rule, `lib/data.js` `check`); a sight or load not in the game's data; a load of another caliber; a `defaultSight` not among its sights; a sight without a height, or a height for a sight it does not carry; a `firstCourse` that is not a course; a `sightLeaf` naming a sight it does not carry or a leaf table the sight does not have; a record that appears twice; an empty list; a set with no playable gun. Use it as the one path for records from anywhere: check, then serve.
- **`fromFiles(raw)`** — wraps each `data/rifles.json` entry as a record with `toRecord(id, entry)` and passes the list through `fromRecords`. The repository's own data goes through the same check as a record from elsewhere.
- **`toRecord(id, entry)`** — one `data/rifles.json` entry (with its `name`) as a gun record. Use it to make the first records for the Spine from the repository's data: `fields.game` is the entry minus `name`.
- **`load(raw, env = process.env)`** — what the server calls at start: with `env.GUN_RECORDS_FILE` naming a JSON file (either a list of records or `{ "records": [...] }`), the set comes from that file; without it, from `data/rifles.json`. Returns `{ rifles, from }`; a bad file or record throws, and the server stops with the message.
- **`GUN_RECORDS_FILE`** — the environment variable: the path of a JSON file of gun records. Set it on the server (for Fly, `fly.toml` `[env]`, or a file the deploy writes) once the records live elsewhere; the server reads it once at start. Nothing reads an outside service.
- **The copy file** (`RD.makeCopy()` / `RD.checkCopy(obj)` / `RD.loadCopy(obj)` in `public/game.js`, "Save a copy" / "Load a copy" on `/book`): `{ kind: "range-day copy", version: 1, savedAt, zeros: [{ rifle, sight, load, zeroYards, elevationClicks, windageClicks, leafIx, saved_on }], book: [{ rifle, sight, load, id, day, n, at, on, course, yards, elevationClicks, windageClicks, elevationMoa, windageMoa, leaf, zero, heldUpMoa, heldRightMoa, tempF, windCall, upIn, rightIn, struck, note }], cold_bore: [{ rifle, id, day, n, at, on, course, sight, load, yards, elevationClicks, windageClicks, leaf, windCall, tempF, hit, upIn, rightIn }], days: [<day records>] }`. `checkCopy` is the whole-file check (kind, version 1, the four lists, each record's required fields and kinds, with null allowed for `leaf`, `zero`, `windCall` and a cold-bore shot's `upIn`/`rightIn`; a zero's and a wind call's own fields; and inside each day its box, weather, three stretches of wind, month, time of day and every shot with where it landed, a shot at steel also its hit and hold); `loadCopy` runs it first and writes nothing from a refused file. The book, cold-bore and zero lines use the field names of the gun record's `measured` section, grouped by `rifle` (and `sight`/`load`), so the first import into a gun's `measured` is: for each gun id, the lines whose `rifle` is that id, the `rifle` field dropped. `id` is `<day id>:<shot number>` and is what "Load a copy" matches on, so a line imported and exported again is the same line; `at` and `n` give the order.
